ArcGIS Velocity Logger Help

Find connection guidance, workflow details, and keyboard shortcuts without leaving the app.

On this page

    Start receiving data

    ArcGIS Velocity Logger captures network data from TCP, UDP, HTTP/HTTPS, WebSocket, gRPC, and XMPP connections. Use it to inspect ArcGIS Velocity outputs, ArcGIS GeoEvent Server integrations, and compatible custom services.

    1. Select a Preset for a paired local Logger and ArcGIS Velocity Simulator test, or select a connection type.
    2. Confirm the host and port, then select Settings for protocol-specific values.
    3. Select Connect. Captured data appears in the log area until you disconnect or apply a configured stop condition.

    A preset only fills editable fields. It never connects, starts capture, saves a password, or changes startup defaults. Selecting Custom preserves current values; editing a populated preset changes its label to Custom (modified).

    Use Protocol Settings

    Select Settings, or press Cmd/Ctrl + Shift + P, to open the resizable Protocol Settings window. The compact connection row holds only preset, connection type, host, port, and connection actions.

    • Basics contains values needed for the selected protocol, such as format, path, serialization, RPC type, or XMPP conversation and account fields.
    • Security contains TLS or STARTTLS policy, certificate paths, certificate verification, and remote binding where applicable.
    • Advanced contains optional headers, subscription messages, first-message handling, and XMPP timing values.
    • Summary provides the read-only effective connection and warnings. Secrets are shown only as Set (hidden), Empty, or Not set.

    Edits apply to the next connection. Done and Escape keep them; Revert changes restores the values present when the window opened; Reset to preset reapplies a modified preset. While connected, Settings opens read-only in Summary mode.

    See the connection summary and Protocol Settings guide for the complete behavior.

    Configure TLS safely

    Client certificate verification is enabled by default whenever TLS or STARTTLS applies. The explicit Allow unverified option accepts an unverified server certificate for any host; traffic remains encrypted, but the server identity is not checked. Keep it off except for a deliberate test such as a local automatic self-signed certificate.

    For HTTP, WebSocket, and gRPC, client mode uses the OS certificate store unless a custom CA certificate is supplied. Server-mode TLS requires a certificate and key. An XMPP server uses an automatic self-signed pair only when both certificate and key are empty; configuring only one is an error.

    See the TLS guide for certificate, trust-store, and mutual TLS guidance.

    Receive from XMPP

    XMPP uses port 5222, Direct conversation, and Required STARTTLS by default. The Logger defaults to server role when XMPP is selected. In client mode, configure the XMPP domain, account, and optional receiving JID filter. In server mode, the live Receiving JID is shown after the server starts.

    • Direct receives one-to-one message bodies. Room (MUC) receives groupchat message bodies and requires a room and nickname.
    • Client passwords and server external-account passwords may be intentionally empty for a local test, but the associated username remains required.
    • Connect and reply timeouts default to 30000 ms and 15000 ms. Client ping and reconnect intervals default to 60000 ms. Each must be a positive whole number.
    • For an XMPP Server, Copy Client Settings is available only while listening and excludes the password unless you explicitly include it.

    For a paired local test, select Local XMPP — Logger Server / Simulator Client in both applications. Connect the Logger first, then connect and start playback in ArcGIS Velocity Simulator.

    Use the XMPP guide for the full setup, conversation semantics, and troubleshooting steps.

    Connect to ArcGIS Velocity

    Select the ArcGIS Velocity sign-in control to browse outputs and apply supported connection settings. Applying an output fills the connection mode, host, port, path, TLS, and format when those values are available. Stored passwords and output secrets are never recovered.

    After you apply a supported output, the Logger can attach its token to supported gRPC metadata, HTTP headers, and WebSocket upgrade headers. The token is refreshed before it expires and is never displayed in the interface.

    See the ArcGIS Velocity sign-in guide for output selection and authentication details.

    Manage captured logs

    Use Save Logs to export the captured data and Clear Logs to remove entries from the current view. Auto-scroll keeps the newest lines visible; list order switches between oldest-first and newest-first views. Enable Show Metadata to add connection or call context before received records.

    For automated capture without the user interface, use headless mode. It supports output formats, filters, stop conditions, an output file, and a completion file. See the headless capture guide.

    Use the command-line reference

    Press F3, select Help → Command Line Interface, or use the toolbar action to open the dedicated command-line workspace. It supports text search, quick filters, sortable columns, visible-row copy/export, and example commands.

    The terminal equivalents are npm run help:cli, npm run help:cli:wide, and npm run help:cli:narrow. See the command-line reference for every option and the configuration guide for saved settings.
