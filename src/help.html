ArcGIS Velocity Logger Help

Getting Started

Capture and log network data from TCP, UDP, HTTP/HTTPS, WebSocket, and gRPC connections. Useful for debugging and monitoring ArcGIS Velocity feeds and other data sources.

Connection Types

  • TCP Server: Listen for incoming TCP connections from clients
  • TCP Client: Connect to a remote TCP server to receive data
  • UDP Server: Listen for incoming UDP datagrams
  • UDP Client: Send UDP datagrams to a remote server
  • HTTP Client: Send data via HTTP/HTTPS POST requests to a remote endpoint (e.g. an ArcGIS Velocity HTTP Receiver feed). Supports JSON, Delimited (CSV), Esri JSON, GeoJSON, and XML formats.
  • HTTP Server: Start a local HTTP/HTTPS server that accepts POST requests from clients. Use for receiving data from the Velocity Simulator or other HTTP senders.
  • gRPC Server: Start a local gRPC server that accepts incoming RPC calls. Supports Protobuf, Kryo, and Text serialization.
  • gRPC Client: Connect to a remote gRPC server using HTTP/2. Supports Protobuf, Kryo, and Text serialization with client-streaming or unary RPCs.
  • WebSocket Client: Connect to a remote WebSocket server (ws:// or wss://) to receive streaming data. Supports JSON, Delimited (CSV), Esri JSON, GeoJSON, and XML formats. Can send a subscription message on connect and optionally ignore the first message.
  • WebSocket Server: Start a local WebSocket server (ws:// or wss://) that accepts incoming client connections and receives data. Supports the same 5 formats as the WebSocket client.

HTTP Options

  • Format: Controls the Content-Type header — JSON (application/json), Delimited/CSV (text/plain), Esri JSON (application/json), GeoJSON (application/geo+json), or XML (application/xml). Must match the format configured in the ArcGIS Velocity HTTP Receiver feed.
  • TLS: Enable HTTPS (port 8443 by default). Uses the OS certificate store automatically in client mode. Server mode requires a certificate and key.
  • CA cert path: Custom CA certificate file (PEM). Leave empty to use the OS certificate store. Only needed for enterprise or self-signed CAs.
  • TLS cert path: Client or server certificate file (PEM). Required for server-mode TLS; only needed in client mode for mutual TLS (mTLS).
  • TLS key path: Private key file (PEM). Required for server-mode TLS and client-side mTLS.
  • HTTP Path: URL path appended after host:port (default /). In server mode, only POST requests matching this path are accepted. In client mode, this path is used in outgoing POST URLs. Set to the Velocity feed's system-generated path (e.g. /receiver/feed-id) when connecting to a real endpoint.

WebSocket Options

  • Format: Controls the expected data format — JSON (application/json), Delimited/CSV (text/plain), Esri JSON (application/json), GeoJSON (application/geo+json), or XML (application/xml).
  • TLS: Enable WSS (WebSocket Secure, port 8443 by default). Uses the OS certificate store automatically in client mode. Server mode requires a certificate and key.
  • CA cert path: Custom CA certificate file (PEM). Leave empty to use the OS certificate store. Only needed for enterprise or self-signed CAs.
  • TLS cert path: Client or server certificate file (PEM). Required for server-mode TLS; only needed in client mode for mutual TLS (mTLS).
  • TLS key path: Private key file (PEM). Required for server-mode TLS and client-side mTLS.
  • Path: URL path appended after host:port (default /). In server mode, only WebSocket upgrade requests matching this path are accepted. In client mode, this path is used in the outgoing connection URL.
  • Subscription Message: Optional text message sent to the server immediately after the WebSocket connection is established. Useful for subscribing to a specific data feed or channel.
  • Ignore First Message: When enabled, the first message received after connecting is silently discarded. Useful when the server sends an initial handshake, welcome, or acknowledgement message that is not actual data.
  • Custom Headers: Optional JSON object of custom HTTP headers to include in the WebSocket upgrade request (client mode only). Example: {"Authorization": "Bearer token123"}.

gRPC Options

  • Serialization: Protobuf (default, external GrpcFeed protocol), Kryo (internal GrpcFeatureService, binary), or Text (internal GrpcFeatureService, UTF-8 CSV).
  • RPC Type: Client Streaming (persistent stream, higher throughput) or Unary (individual request/response per message).
  • TLS: Enable TLS for the gRPC connection. Uses the OS certificate store automatically.
  • Header Path Key / Path: Custom gRPC metadata header for endpoint routing (client mode only).

Velocity Login & Output Picker (🔑)

Click the 🔑 button in the toolbar to sign in to your ArcGIS Velocity organization and browse available outputs. This allows you to auto-populate connection settings without manual configuration.

  • Portal URL: Your ArcGIS Online or Enterprise portal URL (default: https://velocitydemo.maps.arcgis.com).
  • Username / Password: ArcGIS account credentials. A token is generated and automatically refreshed before expiry.
  • OAuth 2.0: Alternative tab for OAuth client credentials. Currently supported only for HTTP Poller outputs.
  • My Outputs / ORG Outputs: Segmented toggle to switch scope. "ORG Outputs" is the default and adds view=admin to fetch all org outputs (requires admin privileges). "My Outputs" returns only your outputs.
  • Refresh ⟳: Re-fetches the output list for the current scope without re-authenticating.
  • Supported / All: Client-side filter toggle that shows only supported output types by default, or all output types including unsupported ones.
  • Output Type dropdown: Filters outputs by type. Each type has a unique icon prefix and colour (see Output Type Reference below).
  • Output dropdown: Select a specific output to view its details. Unsupported types shown with ⚠ prefix and muted styling.
  • Info panel: Displays the output's label, ID, type (with coloured icon badge), URL, auth type, format, and schema fields.
  • Apply: Auto-populates the main window's connection mode, host, port, path, TLS, and format from the selected output. Disabled for unsupported types.
  • Remember me: Persists portal URL and username (not password) across sessions.

Authentication: After applying an output, the Logger automatically attaches a Bearer token to gRPC metadata, HTTP headers, and WebSocket upgrade headers. Token is proactively refreshed at 80% of its lifetime.

Show Metadata - gRPC Client Fields

When Show Metadata is enabled, each received data line is preceded by a [metadata] line. In gRPC Client mode the following fields appear:

FieldValuesMeaning
protocol gRPC Always gRPC for gRPC connections.
mode client Always client when the logger is connecting out to a server.
serialization protobuf, text, kryo The active serialization format selected in the UI.
method stream, unary The configured RPC Type. stream = Client Streaming (persistent HTTP/2 stream); unary = discrete request/response per message.
rpc Watch, watch The server-streaming RPC method the logger called to subscribe to incoming data — the logger sends one request and the server pushes a continuous stream back.
Watch (capital W) — used with Protobuf serialization (GrpcFeed.Watch in velocity-grpc.proto).
watch (lowercase) — used with Text and Kryo serialization (GrpcFeatureService.watch in feature-service.proto).
remote HOST:PORT The address of the gRPC server the logger connected to.
feature N/TOTAL Protobuf only. Which feature within the received batch this data line represents (e.g. feature=1/3 = first of three features in one message).
size bytes Text / Kryo only. Byte length of the raw payload received.

Example metadata line (Protobuf client, one feature in the batch):

[metadata] protocol=gRPC mode=client serialization=protobuf method=stream rpc=Watch remote=127.0.0.1:5565 feature=1/1

Show Metadata — gRPC Server Fields

In gRPC Server mode one metadata line is emitted per incoming RPC call, showing the call headers sent by the remote client:

FieldValuesMeaning
rpc Send, Stream, execute, executeMulti The RPC method the remote client invoked.
Send / Stream — Protobuf (GrpcFeed): unary and client-streaming respectively.
execute / executeMulti — Text / Kryo (GrpcFeatureService): unary and bidirectional-streaming respectively.
remote ipv4:HOST:PORT Remote client address as reported by the gRPC call (e.g. ipv4:127.0.0.1:54321).
local HOST:PORT The local bind address and port the server is listening on.
deadline none or ISO-8601 timestamp The call deadline set by the remote client. none if no deadline was specified.
call headers key=value … All gRPC call metadata key-value pairs sent by the client (HTTP/2 request headers, e.g. content-type=application/grpc, grpc-path=my.feed.uid).

  • Clear Logs: Remove all log entries

Status Bar and Indicators

The footer keeps connection state, TLS, and auth centered. Longer status messages appear in the Activity Strip.

Activity Strip

Appears after the first activity update. It is in the main layout, pinned by default, filters to connection activity by default, and stores newest-first history. Hover the status text for quick details, or click it to keep the details open while logs update.

Application States

Status Indicator Color Description
Connected ● Green A successful connection is established, and the application is ready to send or receive data.
Connecting ● Orange The application is attempting to establish a connection to the specified host and port.
Disconnecting ● Orange The application is in the process of closing the current connection.
Disconnected ● Grey The application is not connected. This is the default state before a connection is initiated or after a connection is successfully closed.
Error ● Red An error has occurred, such as a connection failure or configuration issue. Check the status message for more details.

Command Line Interface

The logger can run from the command line in normal UI mode or in a truly headless mode with no GUI. Press F3, or choose Help → Command Line Interface, or use the toolbar button (>_), or the context menu, to open a dedicated searchable dialog listing every command-line parameter, its default, whether it is required in headless mode, and an example.

  • Search + quick filters: filter by parameter text and switch among All, Required, Optional, Headless-only, and Help-related parameters.
  • Active filter pills: see the current search, category, and sort state at a glance and clear search/category filters directly from the pill row.
  • Copy / export tools: copy example commands, copy visible rows, or export visible rows as TSV, CSV, Markdown, or JSON.
  • Collapsible panels: the Behavior & Help Layouts and Notes sections start collapsed so the main table and examples stay in view.
  • Resizable table area: drag the parameter table taller or shorter inside the dialog as needed.
  • Wider first-open layout: the dialog opens wider by default so the built-in example commands are easier to read immediately.

For terminal help use npm run help:cli, npm run help:cli:wide, or npm run help:cli:narrow. See docs/COMMAND-LINE.md and docs/HEADLESS.md for full details.
